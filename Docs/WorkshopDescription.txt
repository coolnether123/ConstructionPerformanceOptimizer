[h2]Description[/h2]
Requires [url=https://steamcommunity.com/workshop/filedetails/?id=2009463077]Harmony[/url].

Construction Performance Optimizer helps RimWorld stay responsive when your colony has a large construction backlog.

Large building plans and terrain projects can leave the game repeatedly checking hundreds or thousands of unfinished constructions. CPO reduces that unnecessary processing so RimWorld can spend more time advancing the simulation.

You are most likely to notice the benefit with large construction queues, many builders, higher game speeds, or terrain-building mods such as Tilled Soil. The improvement depends on how much construction is active and may be barely noticeable when little is being built.

CPO improves game performance. It does not make pawns build faster or change construction rules.

[h2]What it helps with[/h2]
[list]
[*]Reduces repeated validation work while pawns are actively finishing construction.
[*]Avoids an unnecessary return to the global work search when a pawn can continue eligible zero-cost terrain construction.
[*]Spreads construction checks across game ticks instead of checking every active builder at once.
[*]Preserves vanilla work priorities, material delivery, pathfinding, construction speed, success chance, and final authorization.
[*]Automatically disables the broader optimization if another mod directly conflicts with its safe patch point.
[/list]

[h2]Compatibility[/h2]
[list]
[*]Current release: Version 1.0.
[*]Supports RimWorld 1.0 through 1.6.
[*]RimWorld 1.0 uses the zero-cost terrain continuation optimization only.
[*]Single-player is supported on every listed version.
[*]Multiplayer is supported on RimWorld 1.5 and 1.6. Every player must use the same CPO version and mod list.
[*]Tilled Soil is supported but not required.
[*]No settings and no save data. Normally safe to add or remove between sessions.
[*][b]Do not enable this with Construction Queue Optimizer.[/b] The legacy mod contains the same construction patches.
[/list]

[h2]Advanced technical details[/h2]
[spoiler]
Vanilla can run its full CanConstruct validation every game tick for every pawn actively using a FinishFrame job.

On RimWorld 1.1–1.6, CPO schedules that repeated check with:

(game tick + pawn ID) mod 15 = 0

Each pawn therefore runs the full repeated validation once every 15 game ticks, while stable pawn IDs distribute different builders across different ticks. This skips 14 out of 15 redundant mid-job checks without using random state.

Safety is preserved by an unconditional GenConstruct.CanConstruct check immediately before Frame.CompleteConstruction. If the frame is no longer valid, it cannot complete.

For eligible zero-cost terrain, CPO asks the active vanilla ConstructFinishFrames work giver for the next job and starts the exact job it returns. This avoids ending the placement job only to make the global work system rediscover the same frame. Replacement and prerequisite jobs supplied by other mods remain intact.

The transpilers validate the expected method shape and exact call site before changing IL. The validation cadence and completion guard install or disable as a pair, and the broader optimization fails closed when its compatibility checks find a direct conflict.

Multiplayer uses synchronized map ticks and stable pawn IDs, so every peer makes the same cadence decision without consuming random numbers or maintaining peer-local gameplay state.
[/spoiler]
